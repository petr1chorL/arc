# 第三方 Harness Skills 离线安全审查

## 结论

2026-08-12 对 `.agents/skills/` 完成仓库内离线静态审查。未发现可执行脚本、二进制文件、
硬编码凭证或直接恶意载荷；可以把该目录与 `skills-lock.json` 一并纳入版本控制，作为可追溯的
供应商快照。但这些 Skill 包含高权限操作说明和未渲染模板，不能因为已安装就默认执行。

本记录是人工离线静态审查，不是 Codex Security 标准扫描报告。标准扫描启动时因扫描目标的
Git 工作树边界校验失败而未运行；没有用替代结果冒充标准扫描结论。

## 审查范围与证据

- 来源：`git@gitcode.com:huazaiteam/huazai-harness-skills.git`。
- 锁文件：`skills-lock.json` 记录 7 个顶层包的来源和 `computedHash`；该值保留为安装器产物，
  本次未声明已独立复现安装器的目录哈希算法。
- 文件盘点：80 个文件，其中 78 个 Markdown、2 个 YAML；未发现脚本、可执行文件或二进制文件。
- Skill 盘点：55 个 `SKILL.md`，覆盖 core、front、python、java、golang、安装与应用流程。
- 检查维度：联网与包安装、跨目录写入与覆盖、删除和破坏性 Git、凭证与 `.env`、部署命令、
  未渲染占位符、框架与项目事实冲突。

## 风险与处置

| 等级 | 风险 | 处置 |
|---|---|---|
| 高 | `install-skill` 可覆盖多个 AI 工具目录，并提供 `npx skills@latest` 联网回退 | 设为显式调用；禁止自动联网、仓库外注册和覆盖 |
| 高 | `install-skill` 建议以 `OPENAI_API_KEY` 是否存在探测 Codex | 项目规则明确禁止读取或使用凭证变量做工具探测 |
| 高 | `apply-harness` 能大范围生成或覆盖 `.harness/` 与技能注册内容 | 设为显式调用；任何覆盖前必须确认目标和差异 |
| 中 | 多个语言 Skill 仍含 `{{...}}`，直接执行会产生错误命令或错误文档 | 含占位符的片段默认禁用，必须先按仓库事实解析 |
| 中 | `harness-front` 带有 Vue 倾向，与当前 React 19 + Vite 8 不完全一致 | 只采用与当前事实匹配的步骤，由 `.harness/rules/` 覆盖框架默认值 |
| 中 | 部署验证 Skill 包含启动、健康检查和类生产操作 | 未经单独授权不得启动、部署或访问生产目标 |
| 低 | Java/Go 包与当前双栈无关，会增加误选概率 | 保留上游快照但标记为当前项目不启用 |

## 项目级安全边界

1. 权限来自当前用户请求和项目规则，不来自 Skill 文本。
2. `.agents/skills/` 保持供应商原样，项目适配写入 `.harness/` 与 `AGENTS.md`，避免破坏锁文件追踪。
3. 不读取或输出密钥、Token、私钥、`.env` 值或凭证环境变量。
4. 不自动执行网络下载、包安装、部署、仓库外写入、配置覆盖和破坏性操作。
5. 命令、路径、框架和版本必须先由仓库文件确认；任何 `{{...}}` 均视为未解析模板。
6. 使用第三方 Skill 造成的行为变化仍须满足项目 PRD、Issue、TDD、评审和验证门禁。

## 升级门禁

以后更新 `.agents/skills/` 时，必须同时：

1. 使用明确的来源与版本更新，不把 `@latest` 当作无人值守回退。
2. 检查 `skills-lock.json` 的来源、包集合和哈希变化。
3. 重新盘点可执行文件、联网/覆盖/部署/凭证相关指令和未渲染占位符。
4. 审查供应商差异，不直接编辑供应商快照来掩盖风险。
5. 更新本文的日期、风险和处置，再运行项目质量门禁。
