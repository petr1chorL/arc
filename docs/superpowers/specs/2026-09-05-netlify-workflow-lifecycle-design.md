# 04E Workflow 生命周期设计提案

状态：2026-09-06用户回复“同意”，确认八条治理路由及两个只读审核目录，进入本地实施。
依据：同目录 `2026-09-05-netlify-workflow-lifecycle-contract.md`。不是已完成迁移声明。

## 第一性原理

底层目标是发布一个可追溯、不含跨空间依赖的固定流程定义，而不是启动运行。
必要对象是 Workflow 草稿、节点/边/映射、依赖版本、人工节点的分配目录及版本/审计。
草稿可变、发布版本不可变；权限、引用校验、快照与审计必须在同一数据库事务内完成。
04B/C/D 是此片的前置依赖，不能用浏览器内缓存代替已发布版本。

## 范围选择

已选：八条工作流治理路由，加两个既有只读目录 `/reviewers`、`/review-groups`。
提前读取目录只服务编排和校验；目录管理、Human Task 派发/决策、运行、通知均不包含。
另一方案：目录留到后续，04E 明确禁用 Human 节点的新编排与发布；现有含 Human 草稿可只读。
不采用目录失败返回假空数组，也不代理到旧 Zeabur 补数据。

## 最小架构与兼容

- 沿用身份事务和 `_shared/workflows/{routes,policy,handler,postgres}.ts` 分层；
  休眠 `workflows.mts` 无公共 path，直接 Function URL 404 且不得初始化数据库。
- 保留八路由的完整更新、软删除、成功状态、排序和发布前快照语义。
  请求缺省、别名、null、数值先用 Python 实际请求锁定，再实现 TS；不批量生成 CRUD。
- 新写入状态修正为可读中文草稿/已发布；历史原始行不自动改写。
  非法请求固定 422 不回显 input，损坏历史固定 409；非法图仍使用既有 detail 错误数组。
- 沿用既有节点语义和对象路径，不增加表达式执行器、完整 JSON Schema Runtime 或自动类型推导。
  映射至少拒绝非数组、非法项和空 sourcePath/targetPath；路径语法须对照当前执行解析器写共享用例，
  不能声称静态验证保证运行时字段存在。
- Human 默认组、显式组、审核人及人数必须以当前 Workspace 为边界；不可把外空间组计入阈值。
  非法 SLA/门限类型返回可理解校验错误而非 500。资格可用性的具体规则在共享 fixture 中明确。

## 事务与失败路径

- 编辑、发布、软删除锁同一 Workflow 行；不存在/已删除先拒绝，发布读取锁后最新草稿。
- 依赖按固定顺序取得同空间共享锁，覆盖当前定义状态与实际版本；
  与已有 Agent/Data Object/Rubric/Provider 和身份管理锁序对照后再实现，不反向取 Workspace 锁。
- 插入版本、更新草稿和成功审计同事务；已知版本唯一冲突固定 409，未知 SQL 错误不得伪装成功。
- 发布快照验证历史引用归属并固定 Data Object 版本；之后编辑/停用不能重写已存快照。
- 读目录只投影既有字段；无生产 seed、无用户密钥、无任务生成副作用。

## 页面

显式 `workflows` 迁移模式继承前四片限制。复用 Workflows 页面，不建立第二个完整编辑器。
依赖加载具有 loading/error/retry；失败关闭相关写入口，不转换为空选项冒称加载成功。
Workspace/Workflow 切换隔离所有异步响应；发布成功但历史读取失败只重试读取，不能重复发布。
运行按钮和事件处理函数双重阻断；隔离测试服务未知 API 501，零外呼。

## 实施与验证顺序

1. Python 请求契约与目标安全缺陷 RED/GREEN，再锁定共享 fixture。
2. TS 路由/输入/休眠入口 RED/GREEN；逐条接入 PG 事务，不一次造齐未验证接口。
3. DAG、映射与三类版本引用的正反例；Human 同空间目录与门限/SLA 错误。
4. 真 PG 双 Session 发布/编辑/删除、依赖停用；独立 SQL 核对版本、状态与审计；注入审计失败。
5. 浏览器编排、错误依赖重试、两版不可变历史、刷新与运行阻断；覆盖异步切换。
6. 新全量 Python/前端、既有身份与 04A–D PG、lint/build/deploy:check、双轴对抗审查和文档同步。
