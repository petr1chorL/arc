# 04B Agent 生命周期迁移设计

状态：用户已确认兼容规则，进入本地实施；尚未完成迁移。依据同目录 contract.md 与现有八条治理路由。

## 目标和范围

在与身份、04A 资产相同的 PostgreSQL 内完成：创建草稿、编辑绑定、发布、读取不可变版本、
停用和恢复。复用既有请求/权限/事务处理，单独增加 Agent 模块，不复制身份系统。
不实现 test-runs、模型执行、远程 Agent 外呼，不切生产路由或迁移真实数据。

## 建议确认的有意兼容差异

1. **状态**：新发布写“在线”，新停用写“已停用”，创建/恢复规则不变；编辑/发布保护同时识别
   旧乱码停用状态与正常“已停用”。历史读取保留原值，前端使用既有显示映射；不批量更新历史行，
   不改写历史快照。新增版本仍按现有顺序拍摄发布前快照，再更新 Agent 行状态。
2. **空值**：PATCH 非空字段显式 null 统一 422 固定字段错误，不回显输入；缺省不改。
   modelProviderId null 保留合法解绑语义，不自动清除已复制的模型配置。runtimeManifest null 继续 422。
3. **地址/Secret**：modelBaseUrl 可空，非空必须满足 04A 安全 HTTPS 结构；远程 manifest 的
   endpointUrl 使用同样 URL 结构校验。Secret Ref 只存标签，不解析值。旧不合格配置读取固定 409，
   不自动清洗。用户自由文本和 Schema 不宣称通用 DLP。
4. **错误**：Agent 字段验证不回显原始 input；历史引用、URL、manifest 非法时固定 409。
   名字绑定缺失的既有 Tool/Skill 错误保留人类可理解含义，但不输出任意 metadata 或密钥配置。

选择这些规则是为了保持用户可用状态、合法解绑和故障可解释性，而不是机械保留未处理异常。
不选择将全部 null 忽略，因为那会悄悄改变解绑行为；不选择直接清洗所有旧记录，因为没有数据授权和对账。

## 持久化、绑定与发布

补充确认：用户已明确接受 timeoutSeconds 按整数数值处理；30.0/3e1 等价于30并以整数存储。
仍拒绝非整数、bool、字符串及1–60之外的数值；不主动重写历史记录。

- 八条路由和 capability 沿用 contract.md，POST 发布 201，其他状态按现有 API。
- Provider 缺失/跨空间 404，disabled 422，draft 仍可用；绑定复制其模型配置。
- Tool/Skill 按类型、名称、空间、active 解析，持久化稳定引用及名称；保留旧数组顺序和重复语义，
  不引入新的去重或名称重写。
- 所有 Agent 写操作锁定当前 Agent 行；发布在同事务内校验依赖、计数、生成版本、更新 Agent 与成功审计。
  Provider/Tool 的依赖校验持有行锁至提交，防止检查通过后被并发停用；固定锁顺序，避免交叉锁死。
- 同 Agent 并发发布串行生成 v1.0.0、v1.1.0；不同 Agent 不使用全局锁。
  现有计数生成的候选版本号若已存在，固定 409 并保留原数据，不静默覆盖或重编号。
- 版本列表只读；修改草稿、停用或恢复不得修改已发布快照。成功审计失败时整个写事务回滚。
- 不修改已发布 baseline；本片不增加 schema，生产写入冻结/历史重复版本治理留真实数据切换门禁。

## 页面与运行隔离

- Agents 与 AgentDetail 沿用现有页面/API 封装，补统一迁移模式；同库读取 Provider/Tool/Skill 与版本。
- 资产加载失败显式显示不可用并禁用依赖选择/相关保存动作，不回退空数组制造“无资产”。
- 迁移模式的测试运行按钮和事件处理均阻断；隔离服务未知 API 501，不代理 Zeabur。
- 列表状态计数使用同一显示规范化，避免历史乱码在线状态漏计；不因此修改数据库原值。
- 资产模式与 Agent 模式共用既有单一能力入口，不为各按钮增加独立环境变量。
