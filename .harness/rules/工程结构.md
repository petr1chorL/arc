# ARC.ONE 工程结构规则

## 原则

这是棕地项目结构地图，不是目录迁移任务。新增代码优先进入现有接缝；若当前结构产生真实摩擦，
先通过 Issue、设计和架构审查证明重构范围。

## 前端

```text
src/
├─ api/         HTTP 契约与调用封装
├─ auth/        Session、Workspace 上下文与能力守卫
├─ components/  可复用界面组件
├─ domain/      可独立测试的领域/状态转换逻辑
├─ pages/       Workspace 页面与用户路径
├─ data/        当前演示数据；不得误作真实指标
└─ test/        测试环境配置
```

依赖方向以“页面/组件调用 auth、domain、api”为主；`api/` 与 `domain/` 不应反向依赖页面。

## 后端

```text
apps/api/
├─ app/
│  ├─ routers/   HTTP 路由
│  ├─ main.py    应用装配入口
│  ├─ models.py  SQLAlchemy 持久化模型
│  ├─ schemas.py Pydantic 契约
│  └─ 领域服务、Runtime、Gateway、Worker 与安全模块
├─ tests/        API、领域、迁移、安全与运行测试
└─ pyproject.toml
```

不强制引入模板化 `handler/service/repository/entity` 目录。新模块应围绕一个清晰职责和可测试接缝，
避免继续放大 `main.py` 与已知大型页面热点；是否拆分由具体 Issue 和测试证据决定。

## 跨栈边界

- 前端只通过已声明 API 契约访问后端，不读取数据库或后端 Secret Ref 值。
- 后端是权限、Workspace 隔离、审计和安全出口的最终执行边界；前端守卫不能替代后端校验。
- API 契约变化需同时更新 Pydantic schema、前端类型/封装、失败路径测试和必要文档。
- 部署配置变化需检查根 Dockerfile、Compose、启动脚本、健康接口和 CI 契约的共同影响。
