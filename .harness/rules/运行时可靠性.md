# ARC.ONE 运行时可靠性规则

## 当前定位

ARC.ONE V1.0 Lite 是可运行原型，不是生产级高可用平台。可靠性规则用于守住现有边界，不能用来
宣称尚未完成的 SLO、容量、迁移、备份或灾难恢复能力。

## 失败关闭与隔离

- Provider、远程 Agent API、HTTP Tool 和其他外呼必须经过现有 HTTPS、精确 Host、Secret Ref
  和 Workspace 绑定校验；不允许通过模板引入隐式全局凭证回退。
- 跨 Workspace 资产按不存在处理，发布前与 Runtime 都保留校验。
- 重试必须有限、有明确失败终态；空输出、超时和非法响应不能被包装成成功。
- 错误、日志和审计不得回显密钥或敏感原值。

## 运行与恢复

- 队列领取、租约、心跳、重试、死信、取消和重投沿用当前状态机与审计语义。
- Worker 或 API 失败不能留下“静态页面在线即整体健康”的假健康。
- 任何恢复动作都要说明幂等边界、重复执行风险和人工操作要求。

## 健康与部署

- `/api/health` 和 `/healthz` 是当前部署健康检查接缝，但 HTTP 200 不等于真实登录、Seed、模型
  或业务闭环已经签收。
- 部署相关变更至少运行 `npm run deploy:check`；涉及生产入口时检查启动脚本、镜像和实时健康证据。
- 回滚必须基于明确版本和可执行路径；不可逆数据变化不能声称可自动回滚。

## 可观测与能力声明

- 关键运行事实应关联 Workspace、Run、NodeRun、Trace/Span 或审计上下文。
- 演示 Dashboard、FakeGateway、Noop dispatcher、MCP 测试骨架和自动技术验收必须明确标注边界。
- 只有项目总览列出的人工与生产证据完成后，才能提升相应能力声明。
