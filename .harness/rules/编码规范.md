# ARC.ONE 双栈编码规范

## 通用原则

- 最小改动、显式类型、明确错误、测试先行。
- 匹配现有代码风格，不顺手重构无关区域。
- 用户输入、外部响应和跨 Workspace 引用必须在信任边界校验。
- 密钥只使用后端环境变量名形式的 Secret Ref；禁止进入前端、数据库响应、日志或审计正文。

## React + TypeScript

- 组件和页面使用现有 `.tsx` 风格；状态与副作用遵循 React Hooks 规则。
- HTTP 调用收敛在 `src/api/`；页面和组件不散写重复请求、认证和错误解析逻辑。
- Workspace 路由、能力判断和鉴权复用 `src/auth/` 现有接缝。
- 领域纯逻辑优先放在 `src/domain/`，并用邻近 `*.test.ts` 覆盖。
- UI 行为使用 Vitest + Testing Library；不要只断言实现细节。
- 静态门禁以 `npm run lint`（Oxlint）和 `npm run build`（TypeScript + Vite）为准。
- 不要求 ESLint、Prettier、Redux、Zustand、Axios 或 MSW，除非另有已确认 Issue。

## FastAPI + Python

- 运行时要求来自 `apps/api/pyproject.toml`，当前为 Python `>=3.12`。
- 路由放在现有 `app/routers/` 接缝；领域、执行、Gateway、数据库等逻辑沿用当前模块边界。
- 请求/响应契约使用 Pydantic；持久化使用 SQLAlchemy；不要引入平行 ORM 或迁移工具。
- 外部模型、远程 Agent 和 HTTP Tool 调用必须经现有 Gateway/Runtime 安全边界。
- 失败应结构化、可诊断且脱敏；安全校验失败关闭，不隐式回退到不安全路径。
- 测试使用 pytest、FakeGateway 或明确注入的测试替身；不要访问真实模型或默认业务数据库。
- 不要求 flake8、mypy、black、isort、pytest-cov 或 Alembic，除非另有已确认 Issue 并配置机械门禁。

## 注释与文档

- 注释解释“为什么”和边界，不复述代码。
- 产品能力声明必须同时写明未实现边界。
- 新领域术语写入根 `CONTEXT.md`；难以逆转的架构决策按条件写入 `docs/adr/`。
