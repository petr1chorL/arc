# 编码规范

> **作用域**: 本项目全模块 Go 代码标准与约定。
> **基线**: Go Code Review Comments + Uber Go Style Guide。
> **状态**: 强制 · 由 golangci-lint（go vet + staticcheck）机械化检查

---

## 1. 命名约定

| 元素 | 规则 | 示例 |
|------|------|------|
| 导出变量/函数/类型 | PascalCase（大驼峰） | `RoutePlanningService` |
| 非导出变量/函数 | camelCase（小驼峰） | `calculateTotalCost` |
| 包名 | 全小写、单数 | `route`, `service` |
| 接口 | 以 `er` 结尾 | `Planner`, `Validator` |
| 测试函数 | 以 `Test` 开头 | `TestCalculateTotalCost` |
| 常量 | PascalCase（导出）或 camelCase（非导出） | `MaxCallDepth`, `defaultTimeout` |
| 布尔变量 | 用 `Is` / `Has` / `Can` 前缀 | `IsActive`, `HasPermission` |
| 接收器 | 1-2 字母缩写 | `s *Service`, `r *Route` |

- 禁止拼音与英文混用、禁止无意义缩写（`a1`、`tmp2`）。
- 禁止魔法值：所有字面量常量化。

## 2. 注释与文档

- **所有导出符号必须有注释**，以 `// <符号名>` 开头。
- 包必须有包注释。
- 复杂逻辑用行内注释解释**为什么**，而非**做什么**。
- `TODO` / `FIXME` 必须转化为 `.harness/changes/` 中的任务条目。

```go
// Estimate 估算给定行程的总费用，按交通/住宿/餐饮/门票四类拆分。
// 当数据缺失时返回保守上界估算。
func (s *Service) Estimate(ctx context.Context, plan *TripPlan) (*CostBreakdown, error) {
    ...
}
```

### 2.1 导入规范
- 导入顺序：标准库 → 第三方库 → 本地模块，每组空行分隔
- 用 `goimports` 自动整理
- 禁止 `.` 导入（减少命名冲突）

### 2.2 日志级别约定
| 级别 | 用途 |
|------|------|
| Debug | 开发调试细节 |
| Info | 关键流程节点 |
| Warn | 降级、重试、限频命中 |
| Error | 需人工介入的失败 |

结构化 JSON 日志，含 `timestamp / level / traceId / message / context`。

## 3. 错误处理

| 规则 | 说明 |
|------|------|
| 不吞错误 | 禁止 `_ = fn()` 忽略错误；至少记录日志或转译 |
| 错误分层 | 用 `errors.New` / `fmt.Errorf` + 自定义 error type |
| 错误包装 | 用 `%w` 包装以支持 `errors.Is` / `errors.As` |
| 错误信息 | 包含上下文，但**禁止泄露密钥/隐私** |

```go
// ❌ 禁止
resp, _ := client.Call(req)

// ✅ 正确
resp, err := client.Call(ctx, req)
if err != nil {
    log.Warnf("调用超时, fallback to default, err=%v", err)
    return defaultTemplate(), nil
}
```

## 4. LLM / 外部调用约束（强制）

每一次 LLM 或外部 API 调用必须具备：

| 维度 | 要求 |
|------|------|
| 超时 | 30s（`context.WithTimeout`） |
| 重试 | 3 次，指数退避（1s / 2s / 4s） |
| 限频 | 按业务场景配置 |
| 降级 | 必须有默认值/缓存/离线估算，禁止裸抛到用户 |

### 4.1 统一外部调用治理
- 外部调用能力必须尽量收敛到统一封装层，禁止每个模块各自散写一套超时/重试/限频/降级。
- 同一外部依赖在项目内应只有一套主治理策略。

## 5. 空安全与防御式编程

- public 函数入参做非空/范围校验（返回 error）。
- 返回切片用空切片而非 `nil`（`make([]T, 0)`）。
- 避免 `nil` 传播：链式访问前判空。

---

## 6. 并发与状态

- 共享状态走 Redis / 缓存，禁止全局可变变量持有业务状态。
- goroutine 必须明确生命周期，避免泄露。
- 使用 `sync.WaitGroup` / `errgroup` 管理并发。
- 禁止裸 `go func()` 启动 goroutine 而无退出机制。

---

## 7. 安全红线

| 红线 | 规则 |
|------|------|
| 密钥 | API Key/Token/密码 → 环境变量 或 配置中心，**禁止硬编码** |
| 日志 | 禁止打印 Token、密码、用户隐私 |
| 输入校验 | 所有外部输入必须校验后使用 |
| 竞态 | 共享变量必须用 `sync.Mutex` / `atomic` 保护 |
| unsafe | 禁止使用 `unsafe` 包（除非经 ADR 审批） |

---

## 8. 代码质量量化指标

| 指标 | 阈值 | 守护 |
|------|------|------|
| 文件长度 | ≤ 800 行 | golangci-lint (lll) |
| 函数长度 | ≤ 50 行 | golangci-lint (funlen) |
| 圈复杂度 | ≤ 10 | golangci-lint (gocyclo) |
| 核心逻辑覆盖率 | ≥ 80% | go test -cover |
| 未使用 import/变量 | 禁止 | go vet |
| 竞态检测 | 0 data race | go test -race |

---

## 9. 测试优先编码约定

- 核心业务逻辑、业务规则判断、降级策略默认采用测试先行。
- 每条 AC 应有对应测试映射；每条关键降级路径应有专门测试。
- 测试优先验证**行为与结果**，而不是实现细节。

---

## 10. 提交规范（Conventional Commits）

```
<type>(<scope>): <CHANGE-ID> <简短描述>

type: feat | fix | refactor | test | docs | chore
示例:
  feat(route): C-012 实现超支预警 ≥15% 触发 HITL
  test(budget): C-013 补充离线估算降级测试
```

---

## 11. 简单优先（YAGNI）

- 能用简单方案就不用复杂方案。
- 不为"未来可能的需求"写代码。
- 不引入大型第三方库只为一个小功能。
