# 架构体检技能（Architecture Review）— 前端版

> 扫描代码库，发现"浅模块"，生成可视化 HTML 报告，然后逐个打磨改进方案。

---

## 1. 工作流程

### Step 1: 探索

**先确定范围再扫描——YAGNI。** 关注最近频繁变更的模块。

- 如果用户指定了方向，直接使用
- 否则，用 `git log --oneline` 找热点区域

关注以下摩擦信号：

| 信号 | 说明 |
|------|------|
| **浅模块** | 组件/工具函数几乎和实现一样复杂——没有真正隐藏复杂性 |
| **耦合过深** | 理解一个概念需要跳转多个小文件 |
| **接缝缺失** | 业务逻辑嵌在组件中，无法直接测试 |
| **测试困难** | 核心逻辑无法通过当前接口直接测试，需要复杂的 mock 链 |
| **组件过大** | 单个组件超过 500 行，职责混杂 |

### Step 2: 生成 HTML 报告

写入 OS 临时目录，使用 **Tailwind CDN** + **Mermaid CDN**。

每个候选问题一张卡片，包含：
- **涉及文件** — 哪些文件/模块
- **问题** — 为什么当前架构有摩擦
- **方案** — 浅显易懂的改进描述
- **Before/After 图** — Mermaid 对比图
- **推荐强度** — `Strong` / `Worth exploring`

### Step 3: 打磨循环

用户选择后，运行 `/harnessing` 技能，沿决策树推进。

---

## 2. 对前端项目的特别关注点

- **组件拆分** — 是否过度抽象或过少拆分？
- **状态管理** — 是否存在全局状态滥用（把局部状态放 {{STATE_MGMT_LIB}}）？
- **API 层** — 所有请求是否统一通过 `{{API_FILE}}` 封装？
- **路由设计** — 路由是否按功能模块拆分，懒加载是否到位？
- **依赖管理** — 是否有过大或重复的依赖？
- **响应式支持** — Desktop/Mobile 布局是否合理？
