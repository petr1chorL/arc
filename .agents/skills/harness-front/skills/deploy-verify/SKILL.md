# 部署验证技能（deploy-verify）— 前端版

> **流水线阶段**: ⑥ 第六步 · 收口
> **输入**: 通过 ⑤ CI 的构建
> **产出**: `.harness/changes/<id>/verify.md`
> **出口门禁**: 冒烟 + 健康检查通过，有回滚预案

### 核心规则（一句话摘要）

> **"CI 绿"不等于"线上可用"。确认页面加载正常、核心链路通、降级链路通、有回滚预案。**

---

## 1. 工作流程

### Step 1: 部署
- 确认构建产物已部署到目标环境
- 确认 CDN 缓存已刷新（如有）

### Step 2: 冒烟测试
- 页面能正常加载（无白屏/无 JS 报错）
- 核心功能链路可走通（如登录 → 首页 → 关键操作）
- 控制台无 4xx/5xx 错误

### Step 3: 回滚预案
- 确认上一版本构建产物可用
- 回滚命令：`{{ROLLBACK_CMD}}` 或 CDN 切换
- 回滚后验证核心链路恢复

### Step 4: 输出验证报告

写入 `.harness/changes/<id>/verify.md`：

```markdown
# ✅ 部署验证报告

## 环境
- 环境: dev / staging / production
- 版本: <commit hash>

## 冒烟测试
| 链路 | 结果 |
|------|------|
| 页面加载 | 🟢 |
| 核心链路 | 🟢 |
| 降级链路 | 🟢 |

## 可观测性
- [x] 无 JS 报错
- [x] 控制台无 4xx/5xx
- [x] 埋点上报告警正常

## 回滚预案
- 上一稳定版本: <tag>
- 回滚命令: <cmd>
- 触发条件: <…>

## 结论
✅ 验证通过，变更可交付 / ❌ 失败，退回 …
```

---

## 2. 完成标志

验证通过后，更新 `change.md` 状态 `verifying → done`，变更交付完成。
