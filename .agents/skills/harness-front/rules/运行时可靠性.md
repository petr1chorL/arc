# 运行时可靠性规范

> **作用域**: 约束本项目前端在准生产/生产环境下的高可用、可观测、可回滚与性能要求。
> **定位**: 补充 `工程结构.md / 编码规范.md / 开发流程规范.md`，聚焦"能稳定跑"而不只是"能跑通"。
> **状态**: 强制（生产级交付前必须满足）

---

## 1. 可靠性目标

- 单个外部 API 故障不能导致整个页面白屏
- 所有 HTTP 请求必须可超时、可重试、可降级、可追踪
- 核心用户操作失败时必须能定位到错误
- 生产发布必须有回滚路径

---

## 2. HTTP 请求可靠性基线

所有 HTTP 请求至少满足：
- 明确 timeout（默认 10s，上传可放宽）
- 明确 retry 策略（幂等请求重试 2 次，非幂等不重试）
- 统一错误处理（全局拦截器兜底，组件级可覆盖）
- 错误分类（网络错误 / 4xx / 5xx / 业务错误）
- 请求级别的 loading 状态

---

## 3. 前端稳定性

- 所有组件渲染必须考虑 loading 态、空态、错误态
- 图片加载必须有占位符或 fallback
- 外部 Embed 内容（iframe、第三方脚本）使用 `v-if` 延迟加载
- 避免内存泄漏：`setInterval`、`addEventListener` 在 `onUnmounted` 中清理
- 大列表使用虚拟滚动（`vue-virtual-scroller` 等）

---

## 4. 可观测性

- 关键用户操作上报埋点（页面 PV、按钮点击、API 耗时）
- API 请求失败上报错误详情（`url`、`status`、`message`、`traceId`）
- 前端错误捕获（`window.onerror`、`app.config.errorHandler`）

---

## 5. 性能基线

- 首屏加载时间 < 2s（3G 网络）
- 构建产物 gzip 后 < 500KB（首屏）
- 图片使用懒加载 + WebP 格式
- 禁止在 `setup` 中执行同步耗时的计算
- 大组件使用 `defineAsyncComponent` 异步加载

---

## 6. 安全基线

- 所有用户输入显示前必须转义（Vue 默认自动转义，避免 `v-html`）
- Token 存储使用 `httpOnly` Cookie 或 `sessionStorage`，禁止 `localStorage`
- 敏感信息（Token、密钥）禁止硬编码在前端代码中
- 第三方脚本加载使用 `integrity` 校验

---

## 7. 回滚预案

- 每次构建产物保留上一版本
- 发布脚本必须支持快速回滚（`npm run rollback`）
- 回滚后验证核心链路是否恢复
