# 编码规范

> **作用域**: 本项目前端代码标准与约定。
> **基线**: Vue 3 官方风格指南 + TypeScript 严格模式 + 团队统一 Prettier 配置。
> **状态**: 强制 · 由 ESLint + Prettier 机械化检查

---

## 1. 命名约定

| 元素 | 规则 | 示例 |
|------|------|------|
| 组件名 | 大驼峰 PascalCase | `UserAvatar.vue`、`ChatBox.vue` |
| 文件名（Vue 组件） | 大驼峰 PascalCase | `UserAvatar.vue` |
| 文件名（TS/JS 模块） | 小驼峰 camelCase | `userStore.ts`、`httpRequest.ts` |
| 变量 / 函数 | 小驼峰 camelCase | `isLoading`、`fetchUserList` |
| 常量 | 全大写 + 下划线 | `MAX_FILE_SIZE`、`API_BASE_URL` |
| 类型 / 接口 | 大驼峰 PascalCase、`I` 前缀可选 | `UserInfo`、`ApiResponse<T>` |
| 枚举 | 大驼峰，成员全大写 | `ThemeMode { LIGHT, DARK }` |
| Pinia Store | `use` 前缀 + `Xxx` + `Store` 后缀 | `useUserStore`、`useChatStore` |
| 目录名 | 小写 kebab-case | `coding-skill/`、`user-avatar/` |

- 禁止拼音与英文混用、禁止无意义缩写（`a1`、`tmp2`）。
- 禁止魔法值：所有字面量常量化（放 `constants/` 或枚举）。

---

## 2. TypeScript 规范

- 所有 Vue 组件使用 `<script setup lang="ts">`（Vue 3 项目）
- 开启 `strict: true`，推荐 `noUncheckedIndexedAccess: true`
- 禁止使用 `any`（除非与第三方库兼容需要）
- 函数参数和返回值必须有显式类型
- 使用 `interface` 定义对象类型，`type` 定义联合类型/工具类型
- 不要在模板中写复杂表达式，提取到 computed 或函数

---

## 3. Vue 组件规范

- 组件职责单一：一个文件最好只做一件事
- 组件目录结构：每个组件一个目录，`index.vue` 作为入口

```
components/UserAvatar/
├── index.vue        # 组件入口
└── __tests__/       # 组件测试（可选）
```

- 组件 Props 使用 `defineProps` 声明类型，有默认值用 `withDefaults`
- 组件 Emits 使用 `defineEmits` 声明
- 复杂组件拆分为子组件，禁止单文件超过 500 行
- 模板 `v-for` 必须搭配 `:key`，禁止使用 `index` 作为 key（除非列表静态）

---

## 4. 样式规范

- 优先使用 Tailwind CSS 工具类（如项目采用 Tailwind）
- 自定义样式使用 `<style scoped>`，避免全局污染
- 全局样式放在 `assets/styles/main.css` 或 `style.css`
- 颜色、间距、字体等设计令牌归一化，不写离散值
- 禁止行内 style（极少数动态计算除外）

---

## 5. 状态管理规范

- 全局状态使用 Pinia stores，按业务模块分文件
- 组件内部状态优先使用 `ref` / `reactive`
- 不要在组件中直接修改 store 外的全局状态
- Store 中禁止存放路由参数、临时 UI 状态（用 `useRoute` 读取）

---

## 6. API 请求规范

- 所有 HTTP 请求统一通过 `src/utils/request.ts` 封装
- 封装层必须包含：请求/响应拦截器、统一错误处理、Token 续期
- 禁止在组件中直接调用 `axios` / `fetch`
- API 模块按后端资源划分：`src/services/user.ts`、`src/api/product.ts`
- 处理 loading 状态：`const [data, loading, error] = useFetch(...)`

---

## 7. 路由规范

- 路由文件按功能模块拆分（`router/modules/`）
- 使用路由懒加载：`() => import('@/views/pages/HomeView.vue')`
- 需要鉴权的路由配置 `meta: { requiresAuth: true }`
- 路由守卫写在 `router/index.ts` 或 `router/guards.ts`

---

## 8. 注释规范

- 所有公共函数、工具函数必须有 JSDoc 注释
- 复杂逻辑用行内注释解释**为什么**，而非**做什么**
- 禁止残留 `console.log`、`debugger`、`TODO/FIXME`
- 测试用例使用描述性命名：`should_return_error_when_network_fails`

---

## 9. 不可协商铁律

- ❌ 禁止 `any` 类型（除非无可避免的第三方兼容）
- ❌ 禁止 `console.log` 提交到代码库
- ❌ 禁止直接修改 props
- ❌ 禁止在模板中调用函数（用 computed 或方法）
- ❌ 禁止在组件中直接操作 DOM（用 ref + 指令）
- ✅ 必须使用 `@/` 路径别名，禁止相对路径到处乱飞
- ✅ 每个组件文件 ≤500 行，超过则拆分
- ✅ 函数 ≤50 行，圈复杂度 ≤10
