# 工程结构规范

> **作用域**: 定义本项目的目录组织、模块划分、依赖方向。
> **状态**: 强制 · 违反即阻断 CI

---

## 1. 顶层目录结构（Vue 前端项目）

```
<project-root>/
├── public/                    # 静态资源（不经过构建处理）
├── src/
│   ├── api/ 或 services/      # API 封装层（按后端资源模块分文件）
│   ├── assets/                # 资源文件（图片、图标、字体）
│   │   └── styles/            # 全局样式
│   ├── components/            # 通用组件（按业务模块分目录）
│   ├── config/                # 应用配置
│   ├── constants/             # 常量定义
│   ├── hooks/ 或 composables/  # 组合式函数
│   ├── models/ 或 types/       # TypeScript 类型定义
│   ├── router/                # Vue Router 配置
│   │   └── modules/           # 路由模块拆分（可选）
│   ├── services/              # 服务层（如已用 api/ 则二选一）
│   ├── stores/                # Pinia 状态管理
│   ├── utils/                 # 工具函数
│   │   └── request.ts         # HTTP 请求封装
│   ├── views/ 或 pages/        # 页面视图
│   │   ├── layouts/           # 布局组件
│   │   └── pages/             # 页面（按功能模块分目录）
│   ├── App.vue                # 根组件
│   └── main.ts                # 入口文件
├── index.html                 # HTML 入口
├── vite.config.ts             # Vite 构建配置
├── tsconfig.json              # TypeScript 配置（引用 tsconfig.app.json）
├── tsconfig.app.json          # 应用 TS 配置
├── tsconfig.node.json         # Node 端 TS 配置
├── vitest.config.ts           # 测试配置（可选）
├── eslint.config.ts           # ESLint 扁平配置
├── .prettierrc.json           # Prettier 配置
├── .editorconfig              # 编辑器统一配置
├── .env.development           # 开发环境变量
├── .env.production            # 生产环境变量
├── package.json
└── README.md
```

---

## 4. 模块划分原则

- **按功能域垂直分层**：models/ → services/ → stores/ → views/
- **禁止循环依赖**：composables 不能 import views，views 可以 import composables
- **公共代码下沉**：跨模块共享的逻辑放入 `common/` 或 `utils/`
- **UI 组件 vs 业务组件**：通用 UI 组件放 `components/common/`，业务组件放 `components/<module>/`

---

## 5. 响应式布局规范（推荐）

- 使用 Tailwind CSS 响应式断点（`sm:`、`md:`、`lg:`、`xl:`）
- 复杂页面提供 Desktop / Mobile 双版本组件（如 `UserForm.vue` + `UserFormDesktop.vue`）
- 使用 `useDevice()` composable 检测设备类型（可选）

---

## 6. 依赖方向

```
views/ (页面)
  → components/ (组件)
  → stores/ (状态管理)
  → services/ 或 api/ (API 层)
  → models/ 或 types/ (类型定义)
  → utils/ (工具函数)

禁止:
  - services/ 直接 import stores/
  - components/ 直接 import views/
  - utils/ 直接 import 任何业务模块
```
