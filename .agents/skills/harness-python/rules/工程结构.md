## 2. 模块职责与依赖方向

| 层 | 职责 | 允许依赖 |
|------|------|---------|
| `router/` | 路由注册、URL 映射 | handler |
| `handler/` | 请求处理、参数校验、响应组装 | service, middleware |
| `service/` | 业务逻辑、核心规则 | model, entity, pkg |
| `model/` | 数据模型（ORM） | 无（仅框架 + SQLAlchemy） |
| `entity/` | 领域实体、DTO | 无（仅框架） |
| `middleware/` | 请求拦截、认证、日志 | pkg, exception |
| `pkg/` | 公共工具 | 无（仅标准库 + 第三方库） |
| `tests/` | 测试 | 全部（仅测试作用域） |

**依赖方向（单向，不可逆）**:

```
pkg  ←  model/entity  ←  service  ←  handler  ←  router  ←  tests
  ↑_________↑_______________↑___________↑
      （上游永不依赖下游）
```

## 3. 架构铁律

| 规则 | 描述 |
|------|------|
| R1 | **Service 之间禁止直接依赖内部实现** —— 只能通过接口/契约通信 |
| R2 | **Router 禁止直接调用 Service** —— 必须经 Handler |
| R3 | **pkg 禁止依赖任何业务模块** —— 它是最底层基座 |
| R4 | **Handler 禁止复制业务规则** —— 仅做请求处理和数据组装 |

## 5. 文件组织约束

| 约束 | 规则 | 守护手段 |
|------|------|---------|
| 文件长度 | ≤ 800 行 | flake8 |
| 函数长度 | ≤ 50 行 | flake8 |
| 圈复杂度 | ≤ 10 | flake8 McCabe |
| 一个文件一个 public 类 | 建议 | 人工审查 |

## 6. 新增模块/feature 的目录约定

- 新业务模块 → 在 `service/` 下新增文件
- 新路由 → 在 `router/v1/` 下新增文件
- 新需求 → 在 `.harness/changes/<id>/` 建档（见开发流程规范）
- 新架构决策 → 追加 ADR 到 `.harness/wiki/`
