# 编码规范

> **作用域**: 本项目全模块 Python 代码标准与约定。
> **基线**: PEP 8 + Google Python Style Guide。
> **状态**: 强制 · 由 flake8 + mypy + black 机械化检查

---

## 1. 命名约定

| 元素 | 规则 | 示例 |
|------|------|------|
| 类 / 异常 | PascalCase（大驼峰） | `RoutePlanningService` |
| 函数 / 方法 / 变量 | snake_case（小写下划线） | `calculate_total_cost` |
| 常量 | 全大写 + 下划线 | `MAX_CALL_DEPTH` |
| 包 | 全小写、单数、无下划线 | `route`, `service` |
| 模块 | 全小写、下划线可选 | `route_planning.py` |
| 私有方法/变量 | 前置单下划线 | `_validate_input()` |
| 测试类 | 以 `Test` 结尾 | `TestBudgetService` |
| 测试函数 | 以 `test_` 开头 | `test_trigger_hitl_when_overrun` |
| 布尔变量 | 用 `is_` / `has_` / `should_` 前缀 | `is_active`, `has_permission` |

- 禁止拼音与英文混用、禁止无意义缩写（`a1`、`tmp2`）。
- 禁止魔法值：所有字面量常量化。

## 2. 注释与文档

- **所有 public 模块、类、函数必须有 docstring**，遵循 Google-style。
- 复杂逻辑用行内注释解释**为什么**，而非**做什么**。
- `TODO` / `FIXME` 必须转化为 `.harness/changes/` 中的任务条目，禁止长期遗留。

```python
def estimate(plan: TripPlan) -> CostBreakdown:
    """估算给定行程的总费用，按交通/住宿/餐饮/门票四类拆分。

    Args:
        plan: 待估算的行程方案，不可为 None。

    Returns:
        费用明细；当数据缺失时返回保守上界估算。

    Raises:
        ValueError: 当 plan 为 None 时。
    """
    ...
```

### 2.1 导入规范
- 导入顺序：标准库 → 第三方库 → 本地模块，每组空行分隔
- 用 `isort` 自动整理
- 禁止 `from module import *`

### 2.2 日志级别约定
| 级别 | 用途 |
|------|------|
| DEBUG | 开发调试细节 |
| INFO | 关键流程节点 |
| WARNING | 降级、重试、限频命中 |
| ERROR | 需人工介入的失败 |

结构化 JSON 日志，含 `timestamp / level / traceId / message / context`。

## 3. 异常处理

| 规则 | 说明 |
|------|------|
| 不吞异常 | 禁止空 `except:`；至少记录日志或转译 |
| 异常分层 | 业务异常继承自定义 `AppException` 体系 |
| 异常信息 | 包含上下文，但**禁止泄露密钥/隐私** |

```python
# ❌ 禁止
try:
    call()
except Exception:
    pass

# ✅ 正确
try:
    return client.call(prompt)
except TimeoutError:
    logger.warning("调用超时, fallback to default")
    return default_template()
```

## 4. LLM / 外部调用约束（强制）

每一次 LLM 或外部 API 调用必须具备：

| 维度 | 要求 |
|------|------|
| 超时 | 30s |
| 重试 | 3 次，指数退避（1s / 2s / 4s） |
| 限频 | 按业务场景配置 |
| 降级 | 必须有默认值/缓存/离线估算，禁止裸抛到用户 |

### 4.1 统一外部调用治理
- 外部调用能力必须尽量收敛到统一封装层，禁止每个模块各自散写一套超时/重试/限频/降级。
- 同一外部依赖在项目内应只有一套主治理策略，局部特例必须在 change 或 ADR 中说明。

## 5. 空安全与防御式编程

- public 函数入参做非空/类型校验（用 `isinstance` 或 `pydantic`）。
- 返回集合用空列表而非 `None`。
- 用 `Optional` 类型注解标明可能缺失的返回值。
- 避免 `None` 传播：链式访问前判空，或用 `getattr` 安全取值。

---

## 6. 安全红线

| 红线 | 规则 |
|------|------|
| 密钥 | API Key/Token/密码 → 环境变量 或 配置中心，**禁止硬编码** |
| 日志 | 禁止打印 Token、密码、用户隐私（手机号/身份证脱敏） |
| 输入校验 | 所有外部输入必须校验后使用 |
| 反序列化 | **禁止** `pickle.loads` 不可信数据 |
| 动态执行 | **禁止** `eval()` / `exec()` 执行不可信输入 |

---

## 7. 代码质量量化指标

| 指标 | 阈值 | 守护 |
|------|------|------|
| 文件长度 | ≤ 800 行 | flake8 |
| 函数长度 | ≤ 50 行 | flake8 |
| 圈复杂度 | ≤ 10 | flake8 (McCabe) |
| 核心逻辑覆盖率 | ≥ 80% | pytest-cov |
| 未使用 import/变量 | 禁止 | flake8 |
| 类型注解 | 所有 public 函数必须标注 | mypy |

---

## 8. 测试优先编码约定

- 核心业务逻辑、业务规则判断、降级策略默认采用测试先行。
- 每条 AC 应有对应测试映射；每条关键降级路径应有专门测试。
- 测试优先验证**行为与结果**，而不是实现细节。

## 9. 提交规范（Conventional Commits）

```
<type>(<scope>): <CHANGE-ID> <简短描述>

type: feat | fix | refactor | test | docs | chore
示例:
  feat(route): C-012 实现超支预警 ≥15% 触发 HITL
  test(budget): C-013 补充离线估算降级测试
```

**粒度**: 一个任务一次 commit，message 必须含变更 ID（关联 `.harness/changes/`）。

---

## 10. 简单优先（YAGNI）

- 能用简单方案就不用复杂方案。
- 不为"未来可能的需求"写代码；每个抽象必须有"现在"的价值。
- 不引入大型第三方库只为一个小功能。
